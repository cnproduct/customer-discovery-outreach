# 触达看板与邮件数据

用户需要跟进中的结果或实时看板时，优先接入其现有的本地看板、Zoho/邮件服务商统计或用户授权的数据源。只有在看板/API 明确返回数据时才报告；本地静态 HTML 不能冒充实时数据。

## 指标定义

- **扫描覆盖**：已完整读取的来源记录数 ÷ 当前筛选结果中可读取的记录数。页面只切换分页、但没有滚动采完虚拟列表时，不计为完整覆盖。显示分子/分母、覆盖时间、页/游标范围及失败缺口。
- **已发送**：发送服务记录已接受的邮件数。若来源只有排队状态，不算已发送。
- **已送达/投递成功**：服务商提供投递事件或没有失败的口径；SMTP 提交成功不等同于收件箱送达。明确事件定义。
- **已打开**：使用邮件服务商的开放事件或用户明确认可且透明的追踪数据。图像代理和隐私保护会造成漏计/误计。不得新建隐藏或伪装的追踪像素。
- **已回复**：从授权邮箱/CRM 检索到的人类有效回复，和自动回复、退信通知、退订请求分开。
- **硬退信/软退信**：按邮件服务商的 bounce 分类及 SMTP 状态码区分。重试失败、认证失败等发件端错误不可计作收件人退信。
- **退信率**：在用户确认口径后计算。推荐 `退信邮件数 ÷ 已发送邮件数`；如提供送达数则可同时展示 `退信数 ÷ (已送达 + 退信数)`。去重收件人数与退信邮件事件数分开标明，避免多次投递重复收件人放大/缩小比率。
- **回复率**：有效人类回复的唯一收件人数 ÷ 已发送的唯一收件人数；同时可报告事件口径。
- **二次触达候选**：已首次触达、有证据尚未回复/退信/退订/投诉，且符合用户定义的冷却期。排除所有硬退信、明确退订、垃圾邮件投诉和已回复客户。不能将“不在当前导出里”推断成“从未发送”。

## 数据检查

开始前确定数据连接、最后更新时间、去重键、时区和时间窗口。合并多个 Zoho 邮箱时，按消息/收件人/事件 ID 去重，保留发件账号；无法唯一匹配时报告未匹配数。分别呈现邮件数、唯一客户数和退信事件数。

看板建议显示：累计/时间段已发送、已送达、硬/软退信与退信率、有效回复与回复率、打开数/唯一打开（仅有数据时）、待跟进、各发件账号健康、数据最后同步时间、覆盖口径和最近同步错误。显示来源和指标定义，支持按日期、账号、国家、批次筛选并导出。

## 操作边界

可以读取状态、检查邮箱连接、整理排除名单、生成队列、更新看板和分析效果。当前环境的专用 `email-dashboard` skill 若禁止从 Codex 触发批量冷邮件，应遵守该限制；此处内容不授予额外发送授权。用户要求发送时，完成允许的准备工作后说明剩余人工/授权步骤。不要把邮箱密码、应用专用密码、令牌、cookie 或消息正文批量写入公开仓库/skill。
