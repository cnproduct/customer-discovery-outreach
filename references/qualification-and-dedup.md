# 质量筛选、邮箱判断与去重

## 邮箱层级

对每个邮箱分别记录格式和可用性证据，不要用一个“有效”布尔值混合不同检查：

1. **格式通过**：符合邮箱语法，排除多余空格、明显占位符、重复点和错误域名结构。
2. **域名可解析**：域名有 MX 或合理的邮件接收记录；若只有 DNS/A 记录，应标明仅域名可解析。
3. **服务器接受程度**：仅在合法、供应商允许、现有工具支持时做有限的 SMTP 检查。灰名单、catch-all、隐私保护、速率限制和邮件提供商策略可能导致不确定结果；不得尝试真实发送来验证，除非另有明确任务授权。
4. **历史投递证据**：已记录的硬退信是强烈抑制信号；软退信需看原因和重试结果。用户报告无法触达的地址加入抑制名单，除非用户明确要求审计该地址。

每一层都写明来源和检查时间。验证服务的结果也只是当时信号，不能保证未来投递成功。

## 邮箱和联系人优先级

- 优先企业域名邮箱。
- 常见职能邮箱可保留并标记为通用职能地址：`info@`、`sales@`、`purchase@`、`purchasing@`、`procurement@`、`buyer@`、`sourcing@`、`wholesale@`、`support@`、`care@`、`hello@`、`contact@`。
- 若来源提供联系人姓名与岗位，采购负责人、采购经理、品类/产品经理、品牌负责人、CEO/总经理等与目标相关的个人企业邮箱优先。
- 免费个人邮箱只有在用户允许且存在清楚公司关联/采购或决策角色证据时考虑；否则排除。明显个人无关地址、临时邮箱、学生/政府无关地址、无公司信息地址、占位符及格式错误地址排除并记录原因。
- “个人买家/公司买家”是证据分级，不等同于消费者/企业的确定事实。依据公司官网、职位、域名、公司注册/贸易资料或 CRM 公司字段判别；标为 `公司买家`、`个人买家`、`不确定`，附证据链接/原字段。

## 公司匹配与筛选

- 公司名规范化只用于匹配（大小写、标点、常见公司后缀、空格、Unicode 变体）；原名必须保留。
- 匹配等级：精确/高置信别名、可能匹配、无法确认。仅用户要求“有该公司则保留”且证据可靠时移除确认不存在项；模糊名或集团/子公司关系标记人工复核，不擅自误删。
- 明确排除纯贸易公司、零售散户等画像时，使用可核验的业务描述、产品/工厂证据、网站和贸易数据；有疑问标记待核验。
- 最近联系时间与发送历史是两个独立条件。若用户要求“未发送过开发信”，仅在可访问的 CRM/发送记录覆盖范围内核验，并说明覆盖起止日期和匹配键；不能从公海状态推断从未发送。
- 国家/地区应按来源原值保留，另加标准国家名与时区。未知国家留空/未知，不根据邮箱域名单独推断国家。

## 去重规则

1. 标准化邮箱：去空格、转小写、移除 `mailto:` 前缀。默认以标准化邮箱全局唯一。
2. 对无邮箱条目，用 CRM 客户/公司唯一 ID 去重；没有 ID 时才以规范化公司名 + 联系人名做辅助去重。
3. 与所有已知历史正式导出、发送记录、退信/退订抑制名单和本次输出比对。用户限定去重范围时按其指定范围执行并记下文件/数据源。
4. 处理合并名单时先联合去重再截取目标条数，避免分批各自唯一但合并后重复。
5. 被过滤和重复条目放在拒绝表或审计统计，不默默丢弃。若只交付新增客户，仍报告过滤总数与主要原因。

## 建议记录列

`Email Quality` 使用易读值：格式有效、域名可解析、SMTP 接受、历史硬退信、未知。附 `Validation Source`、`Checked At` 和 `Evidence`。`Email Type` 标注企业域名/通用职能/个人免费/临时或无效。不得把 CRM 中“邮箱字段非空”直接称作邮箱已验证。
