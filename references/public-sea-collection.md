# 小满公海采集与续跑

用于用户已登录并授权访问的小满 OKKI 公海客户数据。页面/接口实际结构会变动；开始前以当前登录页面和可见筛选为准，不假设历史 API 端点仍然有效。

## 采集前检查

- 确认账号当前进入“公海客户”列表，并记录页面可见筛选：邮箱不为空、最近联系时间范围、国家/地区、分页大小及排序。
- 找到并检查现存的原始 CSV/XLSX、进度 JSON/数据库、已完成页码和所有历史交付文件。确认原始数据不是被较小或空文件覆盖；必要时优先从完整 CSV/备份重建工作簿。
- 以规范化小写邮箱作为主去重键；补充公司 ID、联系人邮箱、规范化公司名作为辅助键。邮件字段缺失时不得用公司名相同直接丢弃不同联系人。
- 用户说“重新采集”时仍然保留跨历史导出去重，除非用户明确要求重建重复名单；用户明确指定页面起点时按该页执行。
- 将截止日期按用户所说的相对日期在本次运行时计算，例如“早于半年”以当前日期减六个月为准，并在输出/审计里记录实际日期。日期过滤只作用于明确识别的最近联系字段；字段缺失与日期较新分别计数，不要自动等同。

## 页面采集

当来源是 Chrome 中已打开的 CRM 页面：

1. 检查用户当前选中的浏览器标签、筛选摘要、总记录数、分页大小和当前页。不要打开撰写邮件或更改筛选，除非用户要求。
2. 识别真正滚动的表格容器。逐段滚动并等待虚拟列表更新，累积唯一行键；记录已看到的首/末行 ID 和累计数。直到滚动位置到底且连续等待后没有新行，再判定页面采完。
3. 分页后确认页码或起始游标确实变化，等待渲染完成，再重复滚动。页数、行数和游标要同步记录。
4. 页面无法暴露完整数据时，说明采集范围仅限当前渲染记录，不把“下一页成功”误当作“本页已完整”。优先使用 CRM 自带导出或用户已经授权的正式 API。

如果有可复用、获授权且合法可用的 CRM API 脚本：

- 用已有会话权限；令牌只从当前 CRM 认证流程/安全存储读取，不复制到日志、仓库或回答。
- 先进行只读小样本检查，核对接口返回数、页面数、最近联系时间字段、公司详情邮箱字段和页面实际数据一致。
- 对详情接口设置超时、有限并发和重试上限。每批写 checkpoint；记录失败页后继续可独立页面，不无限重试。
- 若接口返回空页或连续页面无新记录，核实总数和终止条件后停下，不继续虚报扫描范围。

## 断点、重复与输出

进度文件至少保存：运行 ID、筛选快照、起始/当前/已完成页、每页返回行数、滚动完成标志或游标、原始行总数、失败页/错误、接受和拒绝统计、截止日期、输入输出文件及更新时间。页完成状态仅在该页完整遍历并成功落盘后写入。

推荐输出工作簿包含：

- `新增客户`：满足本轮条件且跨历史唯一的客户。
- `拒绝与原因`：重复、缺失邮箱、日期不符、低质量邮箱、无公司信息等可审计原因。敏感值仅保留在用户指定本地结果中，不提交公开仓库。
- `采集摘要`：筛选快照、时间、页码范围、计数口径、重复范围和注意事项。

必须区分 CRM 记录数和邮箱记录数：一家公司可能有多位联系人，一个客户也可能有多个邮箱。不得为凑足目标降低过滤后仍声称所有行均为“有效可触达”。

## 采集节奏与停止

遵从用户提出的低速采集节奏和平台允许频率。出现验证码、权限拒绝、账号安全告警、连续接口异常或数据异常时停止自动请求，保留 checkpoint，说明阻塞原因。不要绕过风控。运行结束后报告最后完整页、实际新增行数和未扫描范围。
